## 1. Wi-Fi の省電力を切る（済み）

省電力が on だと、ラズパイが Wi-Fi の耳をふさいで休みます。
たとえると、電話をマナーモードにしたまま寝てしまう状態です。
犯人ではなさそうでしたが、サーバーは切っておく方が安心なので、そのままにします。

**ラズパイの中**で打ちました。

```bash
sudo iw dev wlan0 set power_save off
```

| 部分 | 意味 |
|---|---|
| `iw dev wlan0` | ラズパイの Wi-Fi の部品（`wlan0`）を操作する |
| `set power_save off` | 省電力を今すぐ切る。再起動すると元に戻る |

```bash
sudo nmcli connection modify mansion-wifi \
  802-11-wireless.powersave 2
```

| 部分 | 意味 |
|---|---|
| `connection modify mansion-wifi` | マンションの Wi-Fi の接続メモを書きかえる |
| `802-11-wireless.powersave 2` | 省電力は使わない（`2` ＝使わない）。次に起動しても切れたまま |

確かめ方：

```bash
iw dev wlan0 get power_save
```

→ `Power save: off` と出れば OK（2026-10-27 確認済み）

## 2. 日記（ログ）を消えないようにする

### 2-1. なぜ必要？

ラズパイの日記は、今は**ホワイトボード**に書かれています。
電源を切ると消えるので、「なぜ倒れたか」があとから読めません。
実際に `journalctl --list-boots` を打ったら、今回の起動の1行しかありませんでした。

```
 今：ホワイトボード（メモリ）
     電源を切ると消える
       ↓
 これから：ノート（microSD）
     電源を切っても残る
```

### 2-2. なぜ最初はホワイトボードなの？

ラズパイ公式が、わざとそう決めています。
microSD は書くたびに少しずつすり減るので、寿命を守るためです。

```bash
grep -rn Storage /etc/systemd/journald.conf \
  /etc/systemd/journald.conf.d/ \
  /usr/lib/systemd/journald.conf.d/ 2>/dev/null
```

| 部分 | 意味 |
|---|---|
| `grep -rn Storage` | 「Storage」（日記の置き場所）という文字を、フォルダの中まで探す |
| `2>/dev/null` | 「その場所はない」というエラーを隠す |

実際に出たもの：

| ファイル | 中身 | 意味 |
|---|---|---|
| `/etc/systemd/journald.conf` | `#Storage=auto` | `#` 付きなので、ただのメモ |
| `/usr/lib/.../40-rpi-volatile-storage.conf` | `Storage=volatile` | 公式の「ホワイトボードにして」 |

### 2-3. ノートにする

公式のファイルは触らず、**自分のファイルを足します。**
番号の大きいファイルが後から読まれて、勝ちます。
自分のファイルを消せば、元に戻ります。

```
 40-rpi-volatile-storage.conf（公式）
   Storage=volatile
        ↓ 50 の方が後に読まれる
 50-persistent.conf（自分）
   Storage=persistent ← こっちが効く
```

ノートには**ページ数の上限（50MB）**を付けます。
上限まで来たら、古いページから捨てるので、すり減りは少しで済みます。

**ラズパイの中**で、3回に分けて打ちます。

**1回目：自分用の設定フォルダを作る**

```bash
sudo mkdir -p /etc/systemd/journald.conf.d
```

| 部分 | 意味 |
|---|---|
| `mkdir` | フォルダを作る |
| `-p` | もうあれば、何もしない（エラーにしない） |

**2回目：設定ファイルを書く**（6行をまとめてコピーして、1回で貼る）

```bash
sudo tee \
  /etc/systemd/journald.conf.d/50-persistent.conf <<'EOF'
[Journal]
Storage=persistent
SystemMaxUse=50M
EOF
```

| 部分 | 意味 |
|---|---|
| `\`（1行目の最後） | 「次の行に続くよ」という印 |
| `sudo tee ファイル名` | 受け取った文字を、管理者の権限でファイルに書く（画面にも出る） |
| `<<'EOF'` 〜 `EOF` | 「ここから `EOF` までの行を渡すよ」という印。`EOF` は「終わり」の合言葉 |
| `[Journal]` | 日記係の設定だよ、という見出し |
| `Storage=persistent` | 日記をノート（microSD）に書く |
| `SystemMaxUse=50M` | ノートは 50MB まで |

→ 画面に `[Journal]` から `SystemMaxUse=50M` までの3行が出れば OK

**3回目：日記係に新しい設定を読ませる**

```bash
sudo systemctl restart systemd-journald
```

| 部分 | 意味 |
|---|---|
| `systemctl restart` | 係（サービス）を再起動する |
| `systemd-journald` | 日記係の名前。SSH は切れません |

**4回目：今までの日記を、ノートに書き写す**

```bash
sudo journalctl --flush
```

| 部分 | 意味 |
|---|---|
| `journalctl --flush` | ホワイトボード（メモリ）の日記を、ノート（microSD）に今すぐ書き写す |

- 再起動（3回目）だけでは、ノートがすぐには作られませんでした（2026-10-27 に実際に起きた）
- 似た名前の `restart`（係の再起動）と `--flush`（書き写し）を、まちがえないこと

### 2-4. 確かめる

```bash
ls /var/log/journal
```

| 部分 | 意味 |
|---|---|
| `ls` | フォルダの中身を見る |
| `/var/log/journal` | ノートの置き場所 |

→ 英数字の長い名前のフォルダが1つ出れば OK（何も出なければ、4回目を打ち忘れている）

設定が本当に勝っているかも見られます。

```bash
systemd-analyze cat-config systemd/journald.conf \
  | grep -n Storage
```

| 部分 | 意味 |
|---|---|
| `systemd-analyze cat-config` | 日記の設定ファイルを、読まれる順にぜんぶ並べる |
| `\| grep -n Storage` | 「Storage」の行だけ、行番号付きで出す |

実際に出たもの（2026-10-27）：

| 行 | 中身 | 意味 |
|---|---|---|
| 21 | `#Storage=auto` | ただのメモ |
| 55 | `Storage=volatile` | 公式（40 番） |
| 59 | `Storage=persistent` | 自分（50 番）。**最後なので、これが勝ち** ✅ |

> ⚠️ `[sudo] password for kimuhiro:` と出たら、ラズパイに入るときと同じパスワードを打つ。
> 打っても何も表示されないのが正常です。止まったと思って他の文字を打たないこと。
> 「違う」と言われたら、**英数** キーを押してから打ち直す。

## 3. 次に落ちたら、日記を読む

### 3-1. 先にやること

1. 電源を抜き差しして、`ssh kimuhiro@homepi` で入る
2. 下のコマンドを打つ（**読むだけ**。何も変えません）
3. 出てきた文字を、そのまま Claude に貼る

`-b -1` は「1回前の起動」、つまり**倒れる前**の日記という意味です。

### 3-2. 日記を出すコマンド

**A. 日記がどこまで残っているか**

```bash
journalctl --list-boots --no-pager
```

| 部分 | 意味 |
|---|---|
| `--list-boots` | 起動ごとに1行ずつ並べる。`0` が今回、`-1` が1回前 |
| `--no-pager` | 1画面ずつ止めずに、全部いっぺんに出す |

**B. Wi-Fi の記録**

```bash
journalctl -b -1 --no-pager \
  -u NetworkManager -u wpa_supplicant \
  | tail -n 100
```

| 部分 | 意味 |
|---|---|
| `-u NetworkManager` | ネットの係の日記だけ |
| `-u wpa_supplicant` | Wi-Fi のパスワード係の日記だけ |
| `\| tail -n 100` | 最後の 100 行だけ（倒れる直前を見たい） |

**C. 電気と Wi-Fi の部品の記録**

```bash
journalctl -b -1 -k --no-pager \
  | grep -i -E "voltage|brcmfmac"
```

| 部分 | 意味 |
|---|---|
| `-k` | ラズパイの心臓部（カーネル）の日記だけ |
| `grep -i -E "voltage\|brcmfmac"` | 「voltage」（電圧）か「brcmfmac」（Wi-Fi の部品）を含む行だけ |

**D. Tailscale の記録**

```bash
journalctl -b -1 -u tailscaled --no-pager \
  | tail -n 60
```

**E. 倒れる直前の全部**

```bash
journalctl -b -1 --no-pager | tail -n 50
```

- 最後の行の時刻が「倒れた時刻」です

### 3-3. 読み方

**① 電気が足りない → 電源を見直す**

| 出る言葉 | 意味 |
|---|---|
| C に `Undervoltage detected!` | 電圧が足りなかった |
| E の最後に何もなく、ぷつっと切れている | 急に電気が落ちたか、固まった |

**② Wi-Fi が切れた → 有線にすれば直る**（B に出る）

| 出る言葉 | 意味 |
|---|---|
| `CTRL-EVENT-DISCONNECTED` ＋ `reason=4` | 何も話さない時間が続いて、親機に切られた |
| `reason=3` または `reason=8` | 親機が「接続を終わらせます」と言った |
| `reason=5` | 親機が混んでいて、これ以上つなげない |
| `reason=34` | 電波が届かず、返事が返ってこない |
| `reason=15` | パスワードの確認が、途中で止まった |
| `CTRL-EVENT-ASSOC-REJECT` | つなぐのを、親機に断られた |

- `locally_generated=1` が付いていれば、ラズパイ側から切った。付いていなければ、親機が切った

**③ マンションのネット側 → 有線でも同じ恐れ**

- B に `DISCONNECTED` がない（Wi-Fi は切れていない）のに、外に出られない
- B に `dhcp4 ... request timed out` や `expire`（住所をもらえない）
- D に `timeout` や `no route to host` ばかり

**おまけ：テザリング説**

- B に `kimuhiro-iphone` が出たあとに切れている → iPhone と一緒に通り道が出ていった

> 言葉の意味は、Claude が一般的な出方から書きました。
> 実機で文言がずれていたら、出力を貼って読み直します。

### 3-4. 分かれ道

| 結果 | 次の一手 |
|---|---|
| ① 電気 | 電源と USB-C ケーブルを見直す（4） |
| ② Wi-Fi | LAN ケーブルを買って有線にする |
| ③ マンション側 | 有線を買う前に、マンション側を調べる |

## 4. 電気が足りているか見る

### 4-1. 今の充電器

| 項目 | 中身 |
|---|---|
| 充電器 | Apple 30W USB-C Power Adapter（A2164） |
| ラズパイに出せる電気 | 5.0V・3.0A |
| ラズパイ 4 の公式のおすすめ | 5.1V・3.0A |

数字の上では、ほぼ足りています。
ただし、公式が 5.1V と少し多めにしているのは、**ケーブルで電気が少し減る**からです。

```
 充電器 5.0V
   │ ケーブル（細い・長いと減る）
   ↓
 ラズパイ 4.8V くらい？
   → 低すぎると、倒れることがある
```

たとえると、ホースが細いと、蛇口をひねっても先っぽの水の勢いが弱くなる感じです。

### 4-2. 調べる

**ラズパイの中**で打ちます。

```bash
vcgencmd get_throttled
```

| 部分 | 意味 |
|---|---|
| `vcgencmd` | ラズパイ専用の健康診断の道具 |
| `get_throttled` | 起動してから、電気不足や熱で困ったことがあるか |

| 出た答え | 意味 |
|---|---|
| `throttled=0x0` | 起動してから一度も困っていない |
| `0x50000` など `5` が入る | 電気が足りなかったことがある |
| それ以外 | 貼って Claude に聞く |

- 再起動するとリセットされるので、**しばらく動かしたあと**に打つのがコツ
- 落ちたあとに知りたいときは、3 の C を見る
