# 手順書 07：入口を Tailscale だけにする

ゴール：**Apache（受付係）の入口を、Tailscale のトンネルからだけにする**こと。
穴だらけの DVWA や家計簿を置く前の、必須の「鍵閉め」です。

---

## 0. なぜ必要？（たとえ話）

今の Apache は、**どの入口からでも入れる**状態です。

```
 今
  Apache の入口
   ├ Tailscale のトンネル ← 自分だけ ✅
   └ マンションの有線 LAN ← 他の住人も？ ⚠️
```

ここに DVWA（穴だらけ）を置くと、同じマンションの誰かが
その穴を踏み台にできてしまうかもしれません。

```
 これから
  Apache の入口
   └ Tailscale のトンネルだけ ✅
      （マンション LAN からは見えない）
```

たとえ：お店の裏口を、自分の合鍵の1つだけにする。
表の扉は、外から見えないように板でふさぐ。

---

## 1. 今の状態を見る（読むだけ）

**ラズパイの中**（`ssh homepi`）で打ちます。

```bash
sudo ss -tlnp | grep ':80'
```

| 部分 | 意味 |
|---|---|
| `ss` | 今ひらいている入口（ポート）の一覧を見る道具 |
| `-tlnp` | TCP の・待ち受け中の・番号表示で・誰が、を出す |
| `grep ':80'` | 80 番（Web の入口）の行だけ |

→ `*:80` や `0.0.0.0:80` と出れば「**全部の入口で待ち受け**」。
これを、Tailscale の番号だけに変えます。

---

## 2. 「待ち受ける入口」を書きかえる

### 2-1. 設定ファイルを開く

```bash
sudo nano /etc/apache2/ports.conf
```

| 部分 | 意味 |
|---|---|
| `nano` | かんたんな文字エディタ（ラズパイの中で使う） |
| `ports.conf` | Apache が「どの入口で待つか」を書くファイル |

### 2-2. 1行だけ直す

いちばん上に `Listen 80` という行があります。これを2行に変えます。

**変更前**
```
Listen 80
```

**変更後**
```
Listen 127.0.0.1:80
Listen 100.101.64.85:80
```

| 行 | 意味 |
|---|---|
| `127.0.0.1:80` | ラズパイ自身の中からだけ（自分用） |
| `100.101.64.85:80` | Tailscale の番号。トンネルからだけ |

- `100.101.64.85` は、このラズパイの Tailscale の番号です
  （`tailscale ip -4` で確かめられます）
- `443`（https）の行は、今はさわりません

### 2-3. 保存して閉じる

| キー | 何をする |
|---|---|
| `Ctrl + O` → `Enter` | 保存する（O は Output） |
| `Ctrl + X` | nano を閉じる |

---

## 3. 起動のときに困らないようにする

### 3-1. なぜ必要？

ラズパイの電源を入れると、**Apache の方が Tailscale より先に起きる**ことがあります。

```
 電源オン
  ① Apache「100.101.64.85 で待つぞ」
     → でも Tailscale がまだ起きてない
     → その番号がまだ無い！
     → Apache が起動に失敗する ✕
  ② あとから Tailscale が起きる
```

これを防ぐため、「**まだ無い番号でも、先に予約していい**」と
ラズパイに許可します。

### 3-2. 許可を書く

```bash
echo 'net.ipv4.ip_nonlocal_bind=1' \
  | sudo tee /etc/sysctl.d/99-nonlocal-bind.conf
```

| 部分 | 意味 |
|---|---|
| `net.ipv4.ip_nonlocal_bind=1` | 「まだ無い番号でも予約OK」の設定 |
| `/etc/sysctl.d/...` | OS の細かい設定を足す場所 |

→ 画面に `net.ipv4.ip_nonlocal_bind=1` と出れば OK

### 3-3. いますぐ効かせる

```bash
sudo sysctl --system
```

| 部分 | 意味 |
|---|---|
| `sysctl --system` | 設定ファイルを全部読み直して、今すぐ反映する |

→ 最後の方に `net.ipv4.ip_nonlocal_bind = 1` と出れば OK

---

## 4. 書き間違いがないか調べて、反映する

### 4-1. 調べる（反映の前に必ず）

```bash
sudo apache2ctl configtest
```

| 部分 | 意味 |
|---|---|
| `apache2ctl configtest` | Apache の設定を試しに読んで、間違いを探す |

→ `Syntax OK` と出れば OK。
別のものが出たら、5 に進まず、出た文字を Claude に貼る

### 4-2. 反映する

```bash
sudo systemctl restart apache2
```

| 部分 | 意味 |
|---|---|
| `systemctl restart apache2` | 受付係を再起動して、新しい入口にする |

---

## 5. 確かめる

### 5-1. 入口が変わったか（ラズパイの中）

```bash
sudo ss -tlnp | grep ':80'
```

→ `127.0.0.1:80` と `100.101.64.85:80` の2行だけになれば OK。
`*:80` が消えていれば成功です。

```
 変更前  *:80            （全部の入口）
 変更後  127.0.0.1:80    （自分用）
         100.101.64.85:80（トンネル用）
```

### 5-2. トンネルからは今までどおり入れる（Mac）

**Mac のブラウザ**で開きます。

```
http://homepi/
```

→ It works! のページが出れば OK（トンネル経由なので、見える）

### 5-3.（任意）マンション LAN からは見えない

Mac をマンションの Wi-Fi にして、Tailscale を切ってから、
ブラウザで `http://192.168.3.162/` を開く。
→ **開けなければ成功**（LAN からは見えなくなった）

- `192.168.3.162` は、ラズパイの有線の番号（手順書 04 で確認）
- 終わったら Tailscale を Connect に戻す

---

## 困ったとき

| 症状 | よくある原因 | やること |
|---|---|---|
| 4-1 が `Syntax OK` にならない | 2-2 の書き間違い | 出た文字を Claude に貼る。まだ reload しない |
| 5-2 でページが出ない | Mac の Tailscale が止まっている | メニューバーで Connect |
| 再起動後にラズパイの Web が死んだ | 3 をやり忘れて、起動時に bind 失敗 | `ssh homepi` で入れる（SSH は別）→ `sudo systemctl status apache2` を Claude に貼る |
| Tailscale の番号が変わった | まれに起きる | `tailscale ip -4` の番号に、2-2 を書き直す |
