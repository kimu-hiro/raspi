# 手順書 05：SSH を鍵で入れるようにする

ゴール：**パスワードなしで `ssh homepi` だけで入れて、パスワードでは誰も入れない**ようにすること。

---

## 0. 全体の流れ（たとえ話）

今は「暗証番号のドア」です。番号を知っていれば、誰でも開けられます。
これを「**合鍵のドア**」に変えます。

| もの | たとえ | 置き場所 |
|---|---|---|
| 秘密鍵（`homepi`） | 合鍵。**絶対に人に渡さない** | Mac の `~/.ssh/` |
| 公開鍵（`homepi.pub`） | 鍵穴。人に見られても平気 | ラズパイの `~/.ssh/authorized_keys` |

```
 Mac                ラズパイ
 秘密鍵（合鍵）     公開鍵（鍵穴）
   │                  │
   └── 合うか試す ──→ ┘
        合う → 入れる 🔓
        合わない → 入れない
```

- 鍵穴（公開鍵）は、合鍵（秘密鍵）からしか作れません
- 鍵穴を見ても、合鍵は作れません。だから鍵穴は人に見られても平気です

| 段階 | やること | どこで |
|---|---|---|
| 1 | 合鍵と鍵穴を作る | Mac |
| 2 | 鍵穴をラズパイに取り付ける | Mac |
| 3 | 「homepi に入るときはこの鍵」と書く | Mac |
| 4 | 鍵で入れるか試す | Mac |
| 5 | パスワードのドアを閉じる | ラズパイ |
| 6 | 本当に閉じたか確かめる | Mac |

---

## 1. Mac で合鍵と鍵穴を作る

### 1-1. いまの Mac の `~/.ssh/`（2026-10-27 に確認）

`.ssh` は、SSH の道具をしまう**鍵の引き出し**です。もうあるので、作る必要はありません。

| ファイル | 中身 |
|---|---|
| `config` | 「どこに・どの鍵で入るか」のメモ帳 |
| `known_hosts` | 前に入ったことがある機械の名簿 |
| `tamachiKimuraHiroshi` | 職場（DAM のラズパイ・GitHub）用の合鍵 |
| `tamachiKimuraHiroshi.pub` | その鍵穴 |

### 1-2. なぜ新しい鍵を作るの？

職場の鍵を使い回さず、**家のラズパイ専用の鍵**を作ります。

| 使い回すと | 専用にすると |
|---|---|
| 職場の鍵を消すと、家にも入れなくなる | 片方を消しても、もう片方は無事 |
| どの鍵がどこに使われているか分からなくなる | 名前を見れば分かる |

たとえると、家の鍵と会社のロッカーの鍵を、別々にしておく感じです。

### 1-3. 作る

**Mac のターミナル**（VS Code）で打ちます。

```bash
ssh-keygen -t ed25519 -f ~/.ssh/homepi -C "homepi-from-mac"
```

| 部分 | 意味 |
|---|---|
| `ssh-keygen` | 鍵を作る道具 |
| `-t ed25519` | 鍵の種類。今いちばんおすすめの、短くて強い種類 |
| `-f ~/.ssh/homepi` | 鍵の引き出しに `homepi` という名前でしまう |
| `-C "homepi-from-mac"` | 鍵穴に付ける名札。「Mac から homepi に入る鍵」という意味 |

聞かれること：

| 画面 | やること |
|---|---|
| `Enter passphrase` | 合鍵に付ける**合言葉**を打つ（何も表示されないのが正常） |
| `Enter same passphrase again` | 同じ合言葉をもう一度 |

- 合言葉は、Mac が盗まれたときに合鍵を使われないための**2つ目の守り**です
- 3 の設定で、Mac が覚えてくれるので、打つのは最初の1回だけです
- 忘れたら、鍵を作り直せば大丈夫です（ラズパイに入る別の道があるうちに）

最後に、四角い絵（`+--[ED25519 256]--+`）が出れば OK。

確かめる：

```bash
ls ~/.ssh/homepi*
```

→ `homepi` と `homepi.pub` の2つが出れば OK

## 2. 鍵穴をラズパイに取り付ける

**Mac のターミナル**で打ちます。

```bash
ssh-copy-id -i ~/.ssh/homepi.pub kimuhiro@homepi
```

| 部分 | 意味 |
|---|---|
| `ssh-copy-id` | 鍵穴をラズパイに送って、取り付けてくれる道具 |
| `-i ~/.ssh/homepi.pub` | 送るのは、この鍵穴（`.pub` の方。合鍵ではない） |
| `kimuhiro@homepi` | 送り先 |

- 最後に1回だけ、**ラズパイのパスワード**を聞かれます（まだ暗証番号のドアなので）
- `Number of key(s) added: 1` と出れば OK

ラズパイの中では、こうなっています。

```
 /home/kimuhiro/.ssh/authorized_keys
   ↑ 「この鍵穴に合う合鍵なら入れていい」
     という名簿。ここに1行増えた
```

---

## 3. 「homepi に入るときはこの鍵」と書く

Mac の `~/.ssh/config`（メモ帳）に書き足します。
書いておくと、`ssh homepi` だけで入れるようになります。

### 3-1. メモ帳を開く

```bash
code ~/.ssh/config
```

| 部分 | 意味 |
|---|---|
| `code` | VS Code でファイルを開く |

（`code` が使えなければ、VS Code のメニューの「ファイル → 開く」で、`⌘ + Shift + .` を押して隠しフォルダを出し、ホームの `.ssh/config` を開く）

### 3-2. いちばん下に書き足す

今ある `tamachiKimuraHiroshi` と `github.com` の部分は、**触りません**。
いちばん下に1行あけて、これを足して保存します。

```
Host homepi
  HostName homepi
  User kimuhiro
  IdentityFile ~/.ssh/homepi
  IdentitiesOnly yes
  AddKeysToAgent yes
  UseKeychain yes
```

| 行 | 意味 |
|---|---|
| `Host homepi` | `ssh homepi` と打ったときの設定だよ、という見出し |
| `HostName homepi` | 本当の行き先（Tailscale の名前） |
| `User kimuhiro` | ラズパイのユーザー名。`kimuhiro@` を打たなくてよくなる |
| `IdentityFile ~/.ssh/homepi` | 使う合鍵 |
| `IdentitiesOnly yes` | この合鍵だけを使う（職場の鍵を試しに出さない） |
| `AddKeysToAgent yes` | 一度使った合鍵を、鍵番（ssh-agent）に預ける |
| `UseKeychain yes` | 合言葉を Mac のキーチェーンに覚えてもらう |

---

## 4. 鍵で入れるか試す

**Mac のターミナル**で打ちます。

```bash
ssh homepi
```

| 1回目 | 2回目から |
|---|---|
| 合言葉（1 で決めたもの）を聞かれる | **何も聞かれずに入れる** 🎉 |

`kimuhiro@homepi:~ $` と出れば OK。

- ここで**ラズパイのパスワード**を聞かれたら、鍵がうまく使われていません。5 に進まず、困ったときを見る

## 5. パスワードのドアを閉じる

> ⚠️ **ここがいちばん大事です。**
> 間違えると、鍵でもパスワードでも入れなくなります。
> ラズパイには画面もキーボードもないので、直すのが大変です。
> **4 で入ったターミナルは、6 が終わるまで絶対に閉じない**でください。
> これが「命綱」です。何かあっても、ここから元に戻せます。

```
 ターミナル① 4 で入ったもの（命綱）
   → 5 の作業もここでやる
   → 6 が終わるまで閉じない

 ターミナル② 6 で新しく開く（試す用）
```

### 5-1. 今の設定を見る（読むだけ）

**ラズパイの中**（ターミナル①）で打ちます。

```bash
ls /etc/ssh/sshd_config.d/
```

| 部分 | 意味 |
|---|---|
| `/etc/ssh/sshd_config.d/` | SSH の受付係（sshd）の、追加の設定ファイルの置き場所 |

→ `50-cloud-init.conf` が出るはずです。
最初に Imager で「パスワードで SSH」を選んだので、そのとき書かれた「パスワードで入っていいよ」の設定です。

### 5-2. 受付係のルールに注意（日記係と逆！）

手順書 03 の日記係は「**後から読んだ方が勝ち**」でした。
SSH の受付係は**逆**で、「**先に読んだ方が勝ち**」です。

```
 日記係（手順書 03）
   40 番 → 50 番
          ↑ 後の 50 番が勝ち

 SSH の受付係（今回）
   10 番 → 50 番
   ↑ 先の 10 番が勝ち
```

なので、自分のファイルは `50-cloud-init.conf` より**小さい番号（10 番）**にします。

### 5-3. パスワードを使わない設定を書く

**ラズパイの中**（ターミナル①）で、6行をまとめてコピーして、1回で貼ります。

```bash
sudo tee \
  /etc/ssh/sshd_config.d/10-no-password.conf <<'EOF'
PasswordAuthentication no
KbdInteractiveAuthentication no
EOF
```

| 部分 | 意味 |
|---|---|
| `10-no-password.conf` | 自分のファイル。10 番なので先に読まれて勝つ |
| `PasswordAuthentication no` | パスワードで入るのは禁止 |
| `KbdInteractiveAuthentication no` | 「キーボードで答える」形の入り方も禁止（パスワードの裏口になるので） |

→ 画面に2行（`PasswordAuthentication no` など）が出れば OK

### 5-4. 書き間違いがないか調べる

```bash
sudo sshd -t
```

| 部分 | 意味 |
|---|---|
| `sshd -t` | 設定ファイルを試しに読んで、間違いがないか調べる（test の t） |

→ **何も出なければ OK**。何か出たら、6 に進まず Claude に貼る

### 5-5. 本当に勝っているか見る

```bash
sudo sshd -T | grep -E "passwordauth|kbdinteractive"
```

| 部分 | 意味 |
|---|---|
| `sshd -T` | 受付係が「最終的に使う設定」をぜんぶ出す（大文字の T） |
| `grep -E "...\|..."` | パスワードに関係する2行だけ出す |

→ こう出れば OK

```
passwordauthentication no
kbdinteractiveauthentication no
```

### 5-6. 受付係に新しい設定を読ませる

```bash
sudo systemctl reload ssh
```

| 部分 | 意味 |
|---|---|
| `reload` | 係を止めずに、設定だけ読み直させる |
| `ssh` | SSH の受付係の名前 |

- 今つながっているターミナル①は、切れません

## 6. 本当に閉じたか確かめる

ターミナル①は**開いたまま**、VS Code で**新しいターミナル（②）**を開きます。

### 6-1. 鍵で入れる？

```bash
ssh homepi
```

→ 何も聞かれずに `kimuhiro@homepi:~ $` と出れば OK。`exit` で出る

### 6-2. パスワードでは入れない？

```bash
ssh -o PubkeyAuthentication=no kimuhiro@homepi
```

| 部分 | 意味 |
|---|---|
| `-o PubkeyAuthentication=no` | わざと合鍵を使わずに入ろうとする（泥棒のふり） |

→ こう出れば**成功** 🎉

```
kimuhiro@homepi: Permission denied (publickey).
```

`(publickey)` は「合鍵でしか入れません」という意味です。パスワードを聞かれなければ OK。

6-1 と 6-2 が両方 OK なら、ターミナル①も閉じて大丈夫です。

---

## 7. 変わらないこと

| こと | 変わる？ |
|---|---|
| ラズパイに入るとき | パスワード → **鍵**（合言葉は Mac が覚えている） |
| ラズパイの中で `sudo` を使うとき | **今までどおりパスワード**を聞かれる |
| `ssh kimuhiro@homepi` と打つ | 今までどおり使える（`ssh homepi` が短いだけ） |

- `sudo` のパスワードは「家の中の金庫の番号」で、入口の鍵とは別物です。忘れないでください

## 困ったとき

| 症状 | よくある原因 | やること |
|---|---|---|
| 1 で `already exists. Overwrite?` | もう `homepi` という鍵がある | `n` で止めて、Claude に相談 |
| 2 で `Permission denied` | ラズパイのパスワードの打ち間違い | **英数** キーを押してから打ち直す |
| 4 でラズパイのパスワードを聞かれる | 3 の書き間違い、または 2 が失敗した | 5 に進まない。3 の中身と、2 の画面を Claude に貼る |
| 5-4 で何か出た | 5-3 の書き間違い | 6 に進まない。出た文字を Claude に貼る |
| 6-1 で入れない | 鍵の設定がどこかおかしい | **ターミナル①で** `sudo rm /etc/ssh/sshd_config.d/10-no-password.conf` → `sudo systemctl reload ssh` で元に戻して、Claude に相談 |
| 6-2 でパスワードを聞かれた | 10 番の設定が負けている | `Ctrl + C` で止める。ターミナル①で 5-5 をやり直して、Claude に貼る |
